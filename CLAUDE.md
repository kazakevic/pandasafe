# PandaSafe

Chrome extension (Manifest V3) for safer browsing. Current scope on `https://www.youtube.com`: block Shorts (toggle) and a user blacklist of channels by @handle.

## Layout

- `manifest.json`: permissions, the declarativeNetRequest ruleset and content scripts.
- `src/rules.json`: static DNR rules (redirects full page loads of `/shorts/*` to home).
- `src/youtube-shorts.js`: content script, `document_start`. Handles YouTube's SPA navigation, which never fires a `main_frame` request, so DNR can't see it.
- `src/youtube-shorts.css`: hides Shorts surfaces (sidebar, shelves, feed items, channel tab). Scoped to `html:not([data-pandasafe-shorts="off"])` so the toggle can turn it off.
- `src/shared.js`: settings defaults and handle parsing. Loaded as a classic script by the popup, background and content scripts, so content scripts share one global scope: don't redeclare its names (or each other's) at top level.
- `src/background.js`: service worker. Enables/disables the static Shorts ruleset and writes one dynamic DNR rule per blocked channel (`/@handle` page loads → home).
- `src/youtube-channels.js`: content script for the channel blacklist. Hides items linking to `/@handle` via a generated stylesheet, hides watch-page recommendations by channel display name (they carry no channel link), and redirects channel and watch pages of blocked channels.
- `src/popup/`: toolbar popup. Shorts toggle, add/remove channels, one-click "Block this channel" for the active tab. Looks channels up on youtube.com to validate the handle and get name/avatar.
- `icons/`: generated by `python3 scripts/make-icons.py` (Pillow). Edit the script, not the PNGs.

Settings live in `chrome.storage.local`: `{ blockShorts: boolean, blockedChannels: [{ handle, name?, avatar? }] }`.

## Development

- No build step, no dependencies. Plain JS/CSS loaded as-is.
- Load: `chrome://extensions` → Developer mode → Load unpacked → repo root.
- After any change, click reload on the extension card, then refresh YouTube. Changes to `rules.json` need the extension reload; a page refresh alone won't pick them up.
- Chrome writes `_metadata/` into the repo when loading unpacked. It's gitignored; don't commit it.

## Git

- Work and commit directly on `main`. Don't create feature branches or PRs.

## Conventions

- Prefer structural selectors (tag names, attributes like `is-shorts`, `a[href^="/shorts/"]`) over visible text, since text is localized. Text matching is the last resort and lives in the JS `hideLabelled` fallback.
- Blocking means redirecting to the YouTube home page, not converting a Short to `/watch?v=`.
- Keep the MutationObserver work batched (one pass per animation frame). YouTube mutates the DOM constantly.

## Verifying selector changes

YouTube renames its components often. Before changing selectors, check them against the live DOM (e.g. Claude in Chrome + `document.querySelectorAll`) on home, a search results page and a channel page, then confirm no visible `a[href*="/shorts"]` remains.

## Known gaps

- The channel "Shorts" tab and the search "Shorts" filter chip are matched by English label only.
- Only `www.youtube.com` is covered (not `m.youtube.com`).
- Channels are blocked by @handle only. A channel page opened via `/channel/UC…` isn't redirected (its videos still are, via the watch-page owner check).
- Watch-page recommendations are matched by display name, so another channel with the exact same name is hidden too.
