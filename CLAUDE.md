# PandaSafe

Chrome extension (Manifest V3) for safer browsing. Blocks a user list of websites (any domain, with its subdomains). On `https://www.youtube.com`: block Shorts (toggle) and a user blacklist of channels by @handle.

## Layout

- `manifest.json`: permissions, the declarativeNetRequest ruleset and content scripts.
- `src/rules.json`: static DNR rules (redirects full page loads of `/shorts/*` to home).
- `src/youtube-shorts.js`: content script, `document_start`. Handles YouTube's SPA navigation, which never fires a `main_frame` request, so DNR can't see it.
- `src/youtube-shorts.css`: hides Shorts surfaces (sidebar, shelves, feed items, channel tab). Scoped to `html:not([data-pandasafe-shorts="off"])` so the toggle can turn it off.
- `src/shared.js`: settings defaults, handle parsing and site parsing (`parseSite` normalizes links/`www.`/`*.` to a bare domain). Loaded as a classic script by the popup, background and content scripts, so content scripts share one global scope: don't redeclare its names (or each other's) at top level.
- `src/background.js`: service worker. Enables/disables the static Shorts ruleset, writes one dynamic DNR rule per blocked channel (`/@handle` page loads → home) and one rule for all blocked sites (`requestDomains`, so subdomains too → `src/blocked/blocked.html#<original URL>`). Also sends tabs already open on a newly blocked site to the blocked page. Fetches the blacklist API (`GET {apiBase}/blocked-websites` and `/blocked-channels`, `Authorization: Bearer <key>` if a key is saved; default base `DEFAULT_API_BASE`) on startup, every 15 minutes (`alarms`) and when the popup asks; a failed fetch keeps the last lists, a 404 means that list isn't offered. The response format is public in `docs/api.md`: keep it in step with the parsers.
- `src/secret-store.js`: keeps the blacklist API key in the extension's IndexedDB, not `chrome.storage.local` (content scripts on youtube.com can read that). Loaded only by the popup and background.
- `src/blocked/`: the page shown instead of a blocked site. Reloads the original URL if the site gets unblocked while it's open.
- `src/youtube-channels.js`: content script for the channel blacklist (own + API channels). Hides items linking to `/@handle` via a generated stylesheet, hides watch-page recommendations by channel display name (they carry no channel link), and redirects channel and watch pages of blocked channels.
- `src/popup/`: toolbar popup. Shorts toggle, add/remove channels, one-click "Block this channel" for the active tab, add/remove websites (several at once), "Block this site", and the API base URL and key (never shown again once saved; dropped when the base URL moves to another host). API sites and channels are listed with an "API" tag and can't be removed in the popup. Looks channels up on youtube.com to validate the handle and get name/avatar.
- `docs/api.md`: public spec of the blacklist API (endpoints, sample responses, minimal server).
- `icons/`: generated by `python3 scripts/make-icons.py` (Pillow). Edit the script, not the PNGs.

Settings live in `chrome.storage.local`: `{ blockShorts: boolean, blockedChannels: [{ handle, name?, avatar? }], blockedSites: ["example.com"], apiBase: "", apiSites: ["example.com"], apiChannels: [{ handle, name?, avatar? }], apiSync: { at?, error? } }`. What's blocked is `blockedSites` plus `apiSites` (`allBlockedSites`) and `blockedChannels` plus `apiChannels` (`allBlockedChannels`); the popup only edits the user's own lists. Site blocking needs the `<all_urls>` host permission (DNR redirects require host access).

## Development

- No build step, no dependencies. Plain JS/CSS loaded as-is.
- Load: `chrome://extensions` → Developer mode → Load unpacked → repo root.
- After any change, click reload on the extension card, then refresh YouTube. Changes to `rules.json` need the extension reload; a page refresh alone won't pick them up.
- Chrome writes `_metadata/` into the repo when loading unpacked. It's gitignored; don't commit it.

## Git

- Work and commit directly on `main`. Don't create feature branches or PRs.

## Conventions

- Prefer structural selectors (tag names, attributes like `is-shorts`, `a[href^="/shorts/"]`) over visible text, since text is localized. Text matching is the last resort and lives in the JS `hideLabelled` fallback.
- Blocking means redirecting to the YouTube home page, not converting a Short to `/watch?v=`.
- Keep the MutationObserver work batched (one pass per animation frame). YouTube mutates the DOM constantly.

## Verifying selector changes

YouTube renames its components often. Before changing selectors, check them against the live DOM (e.g. Claude in Chrome + `document.querySelectorAll`) on home, a search results page and a channel page, then confirm no visible `a[href*="/shorts"]` remains.

## Known gaps

- The channel "Shorts" tab and the search "Shorts" filter chip are matched by English label only.
- Only `www.youtube.com` is covered (not `m.youtube.com`).
- Channels are blocked by @handle only. A channel page opened via `/channel/UC…` isn't redirected (its videos still are, via the watch-page owner check).
- Watch-page recommendations are matched by display name, so another channel with the exact same name is hidden too.
